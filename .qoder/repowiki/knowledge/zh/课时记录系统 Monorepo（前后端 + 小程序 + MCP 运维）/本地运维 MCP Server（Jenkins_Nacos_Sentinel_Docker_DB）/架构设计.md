单文件单体架构，所有逻辑集中在 `server.ts`：
- 传输层：通过环境变量 `MCP_TRANSPORT` 在 stdio（默认，本地进程内通信）与 SSE（HTTP 模式，监听 `/sse` + `/message` + `/health`）之间切换；SSE 模式下用 Node `http.Server` 手动路由并维护 `sessionId -> SSEServerTransport` 映射。
- 工具注册：使用 `@modelcontextprotocol/sdk` 的 `McpServer.registerTool()` 批量声明约 40+ 个 Tool，参数校验统一走 `zod` schema。
- 外部系统集成：按子系统划分 helper 函数块（Jenkins / Nacos / Sentinel / DB），每个子系统封装认证（Basic Auth、Nacos Bearer Token、Sentinel Cookie）与重试/过期刷新逻辑，对外仅暴露纯 HTTP 调用结果。
- 服务发现：SSE 启动后通过 `registerToNacosMcp()` 自动向 Nacos v3 Admin API 注册自身为 `mcp-sse` 协议的服务，同时收集已注册工具的 `toolSpec` 一并上报；可通过 `NACOS_MCP_REGISTER=false` 关闭。
- 依赖方向：`server.ts` → SDK + mysql2/zod/http/crypto → 各子系统 helper → 远端平台 REST API，无内部子模块拆分。
- 部署形态：提供 `Dockerfile`、`Dockerfile.router`、`docker-compose.yml`、`deploy.sh`、`Jenkinsfile`，以容器方式运行并通过 Nacos 注册。
