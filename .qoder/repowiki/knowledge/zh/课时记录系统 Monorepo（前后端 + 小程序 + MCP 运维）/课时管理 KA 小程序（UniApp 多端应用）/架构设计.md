项目采用 UniApp 3 alpha + Vite 构建，按 `src` 目录分层组织：
- 入口与路由：`main.ts` 通过 `createSSRApp` 创建 Pinia 实例并全局注入 `ROUTES`；`pages.json` 使用 `subPackages` 将主包拆为 `pages/main`(teacher/parent)、`pages/class-record` 两个分包，配合 `uniIdRouter.loginPage` 实现登录拦截。
- 状态层：`stores/user.ts`、`stores/student.ts` 使用 Pinia 持久化用户/学生信息。
- API 层：`api/<domain>/index.ts` 按领域（auth、class、course、record、student、teacher 等）拆分模块，统一通过 `utils/request` 的 `post/get/put/del` 调用后端。
- 网络层：`utils/request/index.ts` 封装 `uni.request`，集中处理签名头（x-sign/x-timestamp/x-nonce）、Bearer Token 注入、401 自动刷新（带并发队列）、loading 提示与错误 toast；`utils/crypto` 负责签名生成。
- 页面层：`pages/` 下以功能域划分，`pages/main/teacher` 与 `pages/main/parent` 分别承载教师端与家长端页面，`pages/class-record` 为独立课时记录子应用。
- 组件层：`components/` 提供通用 UI（empty-state、floating-action-button、form-group、form-page、page-footer、search-filter-bar），`uni_modules/` 引入 uni-ui 生态组件并通过 `easycom` 自动注册。
- 类型层：`types/*.d.ts` 按领域定义 Request/Response 接口，被 api 与 stores 共享引用。
依赖方向：pages → api → utils(request/crypto) → uni.request；pages/stores 可读取 config/routes 常量，api 不反向依赖页面。
