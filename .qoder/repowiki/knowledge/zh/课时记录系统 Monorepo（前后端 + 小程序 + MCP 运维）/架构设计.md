本仓库以 monorepo 形式组织四个独立可部署子模块，跨模块协作契约集中在以下层面：
- 网关路由契约：所有前端请求必须带 Gateway 前缀 `/admin/`、`/biz/`、`/auth/`，由 `cr-gateway` 按前缀转发到对应微服务并 StripPrefix=1，前后端均禁止硬编码无前缀路径。
- 共享领域模型：后端 `common` 模块提供实体、DTO/VO、Converter、Service 接口与通用工具（SM2/SM3/JWT），被 gateway/auth/business/admin 四个微服务以及两个前端共同依赖——前端 API 模块的 URL 路径与后端 Controller 一一对应。
- 安全签名契约：小程序端使用 SM2(cipherMode=1, "04" 前缀) 加密密码并通过 SM3 对每次请求加签（`x-sign`/`x-timestamp`/`x-nonce` 头），admin 端走 BCrypt+JWT 无签名；Gateway 层统一校验 JWT 并将用户信息注入 `UserContext`。
- 运行时基础设施：Nacos（命名空间 `course-record`）集中管理所有配置与服务发现，MySQL (`class_times_record`) 为唯一数据源，MCP Server 作为 AI Agent 访问 Jenkins/Nacos/Sentinel/Docker/DB 的统一入口，不直接参与业务调用链。
- 构建与部署：后端 Maven 多模块打包后 Docker Compose 以 `network_mode: host` 启动；前端通过 Vite dev server 代理 `/admin`、`/auth`、`/biz` 到本地 Gateway :9999；临时文件统一落根目录 `.temp/` 并被全局 `.gitignore` 忽略。
